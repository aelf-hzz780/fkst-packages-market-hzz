Signals and the `hzz780` account. It authorizes GitHub Issue, comment, and Close writes required by
the workflow, but it never authorizes a Schedule or an X write.

验收允许流程所需的 GitHub Issue、comment 与 Close 写入，但绝不授权创建 Schedule 或写入 X。

> pushed, CI is green, and the tag is created. Do not substitute a branch or `v0.3.0-rc.2`.

## Timeouts and failure handling / 超时与失败处理

If a hard timeout is reached, stop issuing review commands and fixture writes. Capture the current
Observe snapshot, redacted logs, Issue states, and Trace IDs. A retrying delivery may continue only
within the 20-minute window; any permanent dead letter, duplicate Proposal, unexpected Schedule,
account mismatch, or X queue delivery fails the release. Do not edit business fields or add a replay
comment to turn a timeout green.

达到 hard timeout 后，立即停止新的 review command 与 fixture write，保存当前 Observe snapshot、

permanent dead letter、重复 Proposal、意外 Schedule、账号错配或 X queue delivery 都直接阻塞
发布。不得通过修改业务字段或添加 replay comment 把 timeout 人工变绿。
