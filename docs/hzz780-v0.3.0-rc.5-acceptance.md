## Goal and non-goals / 目标与非目标

The acceptance has two business assertions and one lifecycle assertion. Phase A proves that four
valid but historical Signals receive four explicit `stale-signal-week` triage outcomes and create no
Proposal. Phase B uses four new copies plus an exact package-scoped migration allowlist and proves
that the same COO evidence creates exactly two review Proposals. Phase C starts a new Session without
that allowlist and proves the Phase B authority did not leak across takeover. All three phases must
create zero Content and zero Schedule, show zero X activity through the pre-close final drain, and
retain the immutable write-disabled config until runtime removal.

本验收包含两个业务断言与一个生命周期断言。Phase A 证明四条格式合法但已过期的 Signal 获得
四条明确的 `stale-signal-week` triage，且不创建 Proposal。Phase B 使用另外四份全新副本与精确的
package-scoped migration allowlist，证明同一批 COO evidence 只创建两条 review Proposal。Phase C
启动不带该 allowlist 的新 Session，证明 Phase B authority 不会在 takeover 时泄漏。三个阶段都必须
保持 Content 与 Schedule 为 0，证明截至 Close 前 final drain 的 X activity 为 0，并让不可变
write-disabled config 一直保持到 runtime removal。

This runbook does not test the `aelfblockchain` credential, create an `aelfblockchain` Session,
change the COO producer, approve Content, create a Schedule, or publish a canary. It does not modify
`fkst-hosted` or the official `github-proxy` package. Existing COO Issues `#116/#117/#118/#124` are
read-only source evidence and must remain untouched.
